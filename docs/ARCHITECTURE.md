# 🏗️ المعمارية والاتفاق بين المراحل (Contract)

## رحلة الأمر
```
🎤 صوت → [1] speech.py → [2] intent.py → [3] execution.py → [4] ui.py
          دور 2           دور 3            دور 4              دور 5
main.py (دور 1) بيربطهم | tests/ (دور 6) بيختبرهم | docs/ (دور 7) بيوثّقهم
```

## الاتفاق (بالكلام العادي)
| من | لـ | بيتسلّم إيه | مثال |
|---|---|---|---|
| speech.py | intent.py | الجملة كنص | افتح المتصفح |
| intent.py | execution.py | اسم الأمر (كلمة إنجليزي ثابتة) | `open_browser` |
| execution.py | ui.py | نجح ولا لأ + رسالة | نجح، "تم فتح المتصفح" |

## الشكل التقني (للكود)
```json
مرحلة 1 ← 2:  { "text": "افتح المتصفح" }
مرحلة 2 ← 3:  { "intent": "open_browser", "args": {} }
مرحلة 3 ← 4:  { "ok": true, "message": "تم فتح المتصفح" }
```
- في الـ MVP الـ `args` فاضية دايمًا.
- شكل مخرج التنفيذ المعتمد هو `ok` (مش `status`).

## أسماء الأوامر الثابتة للـ MVP
| الجملة | اسم الأمر |
|---|---|
| افتح المتصفح | `open_browser` |
| ارفع الصوت | `volume_up` |
| اطفي الجهاز (بعد تأكيد) | `shutdown` |

## قيمة إضافية للفريق يأكدها
- لما الجملة مش مفهومة، `intent.py` بيرجّع `{"intent": "unknown", "args": {}}` و`main.py` بيرد "مش فاهم". (الاسم `unknown` اتضاف في الهيكل المبدئي، والفريق يوافق عليه أو يعدّله.)

## الأمان
1. Allowlist إجباري: أي أمر برّا القايمة بيترفض.
2. ممنوع `shell=True`.
3. الإطفاء لازم تأكيد صريح.
4. الوضع الافتراضي للتجربة هو Dry-Run (بيطبع الأمر من غير ما ينفّذه).
